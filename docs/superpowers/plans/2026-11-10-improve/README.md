## What was audited, and what was not

before planning): correctness of the client, worker loop and deferral paths; security
of everything added since the 2026-10-28 review (client, reply parser, static file

field writes) plus a second look at files, forms, HPACK and the TLS handshake;
performance outside the CI gates; test coverage; tech debt; dependencies, tooling, docs.

stream accounting, resume and close (`h2_on_data`, `h2_block`, `h2_pump`); the
WebSocket read path; the Huffman decoder. No test or build was run during the audit.

## Findings not planned (open — pick up when wanted)

**Re-checked 2026-11-16 against `main` at `d7554d0` (1.17.0):** all six plans above are on
`main` (#127, #129). Of the findings below, every one is still open as written, with
two changes:

- *README quick start uses `import tuntii.viltrum`*: **verified OK**. A copy laid out
  as `v install` does (`~/.vmodules/tuntii/viltrum`) builds `import tuntii.viltrum` and
  resolves its internal `viltrum.http1` imports (V 0.5.2, Linux).
- *`scripts/install.sh` on Windows*: **verified broken**. Under Git Bash (`MSYS` unset)
  `ln -sfn` copies the repo instead of linking it, so later edits do not reach
  `~/.vmodules/viltrum`. Fix: `cmd //c mklink /J` on MINGW/MSYS, as CI does.
- *0.x leftovers*: the `benches/httparena/Dockerfile` default is now a commit
  (`33d6612`, 2026-10-30), not `v1.2.0`; the rest of that item stands.

- **Router scans every route for a parameterised request** (`router/router.v:117-122`):
  cost grows with the number of routes of all methods; separate from the known
  404/405 gap. Wants a many-routes scenario in `benches/fast` first so the win is
  measured.
- **Leaving a topic is a linear search** (`engine/ws.v:298-309`): N subscribers of one
  topic disconnecting together cost O(N²) on the worker.
- **The PR perf gate measures HTTP/1.1 cleartext with three routes only**
  (`benches/fast/server.v:43-47`): HTTP/2, TLS, WebSocket, static files and fetch are
  not gated.
- **Engine socket tests**: `free_addr` closes its probe socket before the server binds
  (a port race under `SO_REUSEPORT`), about 25 s of fixed sleeps in
  `engine/serve_linux_test.v`, and the dial/Reader/free_addr helpers copied in three
  test files. (From the audit report; not re-verified line by line.)
- **A queued fetch past its deadline is still sent upstream, and answers `.timeout` up
  to two sweeps late** (found while executing plan 004; from reading
  `engine/client_linux.c.v` `sweep_peers` / `peer_close`, consistent with
  `test_queued_fetch_times_out` taking more than 2.9 s with a 1 s timeout, not traced
  in a debugger): `sweep_peers` first fails in-flight peers, and `peer_close` hands the
  freed connection to the oldest queued fetch without looking at its deadline, before
  the loop that expires queued fetches runs. That fetch is written to the upstream with
  a deadline already past and times out one sweep (1 s) later, and the same can repeat
  once more. Fix sketch: expire the queue before the peer loop, or skip expired items
  in `next_queued`. The test's bound was widened from 2.9 s to 5.9 s rather than fixed.
- **`engine/serve_linux_test.v` is load-sensitive** (verified 2026-11-10 on the
  unmodified commit `acb27f3`): run as `v test http1/ http2/ jsonenc/ router/ engine/ tests/`
  in ONE command (34 files, 8 parallel jobs) it failed 2 of 2 times on an 8-vCPU VM, on
  timing assertions (`< 40 ms` "a worker was held by a waiting request", `< 550 ms` in
  the h2c deferred test); alone, or one directory per command as CI and
  `scripts/check.sh` do, it passes. Executors: run the directories one per command.
- **HTTP/1.1 and HTTP/2 copies of stream/defer/validation logic** (`engine/stream.v`
  vs `engine/h2_stream.v`, `engine/process.v` vs `engine/h2.v`), about 120 lines.
  Worth doing only after the perf gate has an HTTP/2 scenario.
- **Stop is not graceful**: pending responses are dropped on SIGTERM
  (`engine/worker_linux.c.v:146-152`). Plan 005 fixes the wording; a real drain window
  is a feature decision.
- **Release does not wait for CI** (`.github/workflows/release.yml:23`).
- **0.x leftovers**: `benches/compare/`, `benches/HTTP_PROFILE.md`,
  `docs/superpowers/`, stale `.gitignore` entries; `benches/httparena/Dockerfile`
  defaults to `VILTRUM_REF=v1.2.0`.
- **`scripts/install.sh` on Windows**: `ln -sfn` under Git Bash may copy instead of
  link (CI uses `mklink /J`). Not verified.
- **README quick start uses `import tuntii.viltrum`**, every guide uses
  `import viltrum`; whether a `v install`-ed copy resolves its internal

## Findings considered and rejected

- **Dot-segments in a forwarded `c.path()` reach the upstream**: depends entirely on
  how the upstream normalises paths; changing `fetch_valid` would refuse legitimate
  targets. Handled as a documentation note in plan 005.
- **Empty files are not charged to the static file cache budget**
  (`http1/file_cache.v:55-65`): only grows when the served tree contains a directory
  symlink to its own parent; operator-controlled.
- **Split `engine/h2.v` (1,508 lines) / `engine/worker_linux.c.v` (909)**: each covers
  one protocol or the loop; splitting only moves code.
- **Pin GitHub actions to commit SHAs; cache the V 0.5.2 download**: only GitHub-owned
  actions are used; the download takes seconds.
- **"Views dangle after an array grows"**: rejected in the 2026-10-28 review (V's
  `ensure_cap` keeps the old block; Boehm runs with interior pointers) — not re-raised.
- **Missing `serial` in the client's `Waiter`** (the design doc lists one, the code has
  none): harmless — a timeout closes the upstream connection, so each waiter has one
  answerer. Doc drift only; correct `docs/design/1.x-client.md` when it is next edited.
- **Make nine internal `engine` functions private** (`lend`, `settle`, `resume`, ...):
  same class as the accepted "Ctx exposes internals" gap in ROADMAP.md.
- **`package-lock.json` size**: required by `npm ci` in the release job.
